## 一、先说诊断：你指出的三条，具体错在哪

我把现在这版（你截图里的）和 `Design/V2/02-scan-and-cleanup.md` 的要求逐条对了一遍。
每一条都能落到一个具体的实现决定上，不是"感觉不好看"。

### 1. 重点不突出 —— 三个"第一眼"，互相打架

| 位置 | 现在画了什么 | 问题 |
|---|---|---|
| 头部 | `151 个项目` + `可处理空间 14.74 GB` 两段同权重文字 | 和下面的 chip 数字重复，占掉了标题该有的重量 |
| 筛选行 | 5 个**实心胶囊**，选中的是**纯深绿填充块** | 整个页面最重的一笔，给了一个"换视图"的控件，而不是给主操作 |
| 右栏 | `4.6 GB` 42 pt | 真正的主指标，却和上面的胶囊一样抢眼 |
| 底部 | `移入废纸篓` 深绿实心按钮 | 页面唯一应该最重的东西，视觉权重排在第三 |

结果是：眼睛先在绿色胶囊上落一下，再被 42 pt 的数字拽一下，最后才找到按钮。
**一个页面有三个"最重"的元素，等于没有重点。**

### 2. 信息杂乱 —— 同一件事被说了 2～3 遍

按你截图里的实际文本数一遍：

- **总数**：头部 `151 个项目`、chip `全部 151 个项目`、"扫描结果"右边什么也没有 —— 说了 2 次。
- **可清理量**：头部 `可处理空间 14.74 GB`、右栏 `4.6 GB`（已选）、chip `垃圾 10.03 GB` —— 三个不同的数字，都没有单位说明它们的关系，用户无法判断"14.74 和 4.6 差在哪"。
- **"默认已选中"**：安全组标题右边一次。
- **"需要你确认"**：组标题说了一次组名，行内没有解释 —— 但这组恰恰是最需要解释的一组。
- **权限**：`完全磁盘访问权限` 一张卡片 + 标题 + 打开系统设置 + 底部重启提示 + 三行目录 —— 占掉整整一屏，而这在最常见的"全盘权限已给"情况下是纯噪音。
- **重复文件**：一个独立的 `SiftPanel`（带边框的卡片），里面有图标块、标题、136 组、2.7 MB、"全选"、"Sift 默认保留最早的那一份…"两段说明、分隔线、然后是行 —— 它在页面里长得**和其他所有内容都不是一个物种**。

### 3. 排版杂乱 —— 四种容器语言混用

1. 页头：无容器，靠 hairline 分隔
2. Chip 行：5 个实心圆角块
3. 结果列表：无容器，但安全组的行**整片铺了浅绿底**（这是最刺眼的一处——4 行连成一大块绿）
4. 重复文件：白底 + 1 pt 边框 + 10 pt 圆角的**卡片**
5. 权限：无容器
6. 右栏：无容器，但底部有一个浅绿实心块包着按钮

**行距也不统一**：安全组行高约 56，确认组行内多了一行灰色小字（"逐项确认后才可清理"），实际高度比安全组更高 —— 但信息量并没有更大。

## 二、设计原则（三条，用来裁决后续所有细节）

1. **一屏一个焦点。** 主操作（移入废纸篓）是页面上唯一的重色块。其余一切靠字重、留白和 hairline 分层。
   → 深绿实心只出现在**按钮**上，不再出现在筛选控件上。

2. **一个事实只出现一次，且出现在它被使用的地方。**
   → 总数只进页头；分类量只进 chip；已选量只进底栏；说明只在**帮助决策的位置**出现一次（不进每行）。

3. **一种容器语言。** 页面内容是"无容器的列表 + hairline"，只有两类东西可以拥有自己的边界：浮层（sheet/popover）和真正可交互的独立对象。
   → 重复文件不再是卡片，它就是一个和其他组同级的**分组**。

### 3.1 页头
- 标题 26 pt（现 28 pt 略收，让底栏的数字不吃亏）。
- 副标题一行三段：**什么时候扫的 · 找到多少 · 能清多少**。都用 `·` 连接，都在 12.5 pt / secondary。
  - 这与 `SiftPageHeader` 现有的 `subtitle` + `subtitleDetail` 两个槽位一一对应，不需要改组件签名。
- 右侧只有一个 ghost 按钮「重新扫描」。

### 3.2 筛选
- 从**实心胶囊**改为**下划线 tab**（macOS 原生分段语义）。
- 选中态：`actionGreen` 文字 + 2 pt 下划线。**不再使用深绿填充块。**
- 数字作为次级信息跟在标题后面（11.5 pt / quiet），选中时同色。
- 排序控件保留在右端，纯文字 + chevron，去掉边框。

> 这么做把页面上最大的一块深绿让给了主操作按钮。这是"重点突出"的核心改动。

### 3.3 分组（这是"信息杂乱"的主要来源）
统一成一种分组标题：

```
[图标] 组名   计数   总大小         …右端…         [可选动作] [展开/收起]
```

- **可安全清理**：`✓` 绿色图标。展开。右端动作 `取消全选`（当全选时）/ `全选`。
- **需要你确认**：`⚠` 琥珀色图标。**组标题下只有一句**通用的说明；**任何一行都不再重复它**。
  - 现在的实现每行都带一句 `逐项确认后才可清理`（见 `SmartScanView.swift` 的 review 组），这是最典型的"重复信息"。删掉。
- **重复文件**：不再是 `SiftPanel` 卡片，改成普通分组 + `查看` 链接。展开后行内嵌套，见 3.5。
- **受保护**：默认收起，标题直接写明「不参与清理」，一个 `🔒` 图标代替勾选框。

组间距：组标题上 margin 12，组内行高 50，组与组之间不留额外空白 —— 靠标题的字重区分，不靠空隙。

### 3.4 行
- 高 50 pt，两行：**名称 13.5/500** + **路径 11.5/secondary**。
- 右侧只有**一个**数字：大小，等宽数字，右对齐，固定 92 pt。
  - 去掉行内所有风险徽章 —— 风险是组的属性，组标题已经说了。
  - 去掉行内 chevron —— 整行可点开详情，不需要额外图标。
- **选中态只由勾选框承担**，行底不上绿。
  - 理由：默认全选的安全组会变成 4 行连成一大块绿（现在就是这个效果），
    绿色从"状态"退化成"背景"，勾选框反而看不清。
  - 行底 wash 只用于 **hover**（`rowHoverFill`），和选中是两个不同的东西。
- 未选中的 review 行用 `muted`：名称字重 400、secondary 色，让"未选"在视觉上后退。

### 3.5 重复文件（`02-scan-duplicates.png`）
- 点「重复」tab 后，**页面只显示重复文件一组**（其他组隐藏）—— 当前实现是"过滤后仍显示所有组"，会让人以为结果变少了。
- 组内：每组一个小标题（文件名 · N 份 · 可释放 X），下面 4 行成员。
- **所有副本使用同一种方形勾选框，默认均不选中**。扫描器可以给出推荐，但页面不替用户应用这个推荐。
- 用户逐个选择要移入废纸篓的副本；组标题的「全选」只在用户主动点击后生效，并随即变为「取消全选」。
- 这个配置对应 invariant 44：重复文件的选择必须由用户明确作出，不存在默认保留项或默认删除项。

### 3.6 权限提示
- 从"一张卡片 + 三个可展开目录 + 底部重启说明"压缩成**一行**：
  ```
  ⚠ 13 个位置无法读取，需要完全磁盘访问权限        [打开系统设置] ⌄
  ```
- 展开才显示目录列表和重启说明。
- 数字是**可行动的数量**（`isActionable`），不是全部跳过数 —— 与 invariant 43 一致。
- **当 0 个可行动位置时，这一行整行不显示。** 现在的情况是：即使只有 `systemRestricted`（无解），也占掉一屏。

### 3.7 底部操作栏（替代右栏）
**这是最大的结构改动：删掉右侧 272 pt 的 inspector 栏，改成横跨全宽的底部栏。**

理由：
1. 右栏在 1440 宽下占 272 pt（19%），但内容只有"一个数字 + 一行字 + 一个按钮"，**60% 是空白**（你截图里非常明显）。
2. 列表因此少了 272 pt 的宽度 —— 路径列被压缩，`~/Library/Developer/Xcode/DerivedData` 这类长路径更早截断。
3. 底部栏天然符合"列表是主体"（`02 §1`、`02 §9` 的要求），并且和 macOS 的列表型 App（Finder、App Store）一致。
4. 现有代码里**已经有** `bottomBar` / `selectionStrip` 两套窄屏实现 —— 这次是把它们提升为唯一的实现，**减少**代码路径。

底部栏布局：
```
4.6 GB   已选 37 项，共 151 项              [全选可清理项] [取消全选]  [🗑 移入废纸篓]
         其中 3 项需要确认 · 移入废纸篓后可恢复
```
- 数字 27 pt semibold（不再是 42 pt —— 42 pt 在底栏会压过标题）。
- 第二行同时承担两件事：**风险拆分**（3 项需确认）+ **可恢复性**（移入废纸篓后可恢复）。这两条原本分别在右栏的 `riskBreakdown` 和 `summaryHint` 里。
- 选中 0 项时：按钮变 disabled（`controlFill` 底 + `quietText`），并显示 `选几项后即可清理`。

## 四、连带删掉的东西（这部分是"排版杂乱"的解药）

| 删除项 | 理由 |
|---|---|
| 右栏 `selectionColumn`（272 pt） | 见 3.7，内容搬进底栏 |
| 右栏的分类明细 (`categoryBreakdown`) | 4 行小字，路径/大小已经在列表里；它是"再抄一遍" |
| 右栏的风险徽章行 (`riskBreakdown`) | 折叠成底栏一行文字 |
| 每组行内的风险徽章 | 风险是组的属性 |
| 每行重复的 "逐项确认后才可清理" | 整组一句 |
| 重复文件的 `SiftPanel` 外框 + `IconTile` | 与其他组统一为普通分组 |
| 头部的 `可处理空间` 与 chip 的数字重复 | 头部一行说清三个数 |
| Chip 的实心深绿填充 | 改为下划线 tab |
| 整组连片的浅绿底 | 改为只由勾选框表达选中，行底只做 hover |

## 五、需要你拍板的三点

1. **删掉右栏改底部栏** —— 结构改动最大，但收益也最大（列表更宽、页面不再半边空）。如果你希望保留右栏，我可以做一版"右栏保留但收紧到 240 pt 且去掉分类明细"的对照稿。
2. **筛选改为下划线 tab** —— 和现有 `SiftFilterChip` 组件冲突（它是胶囊）。要么改这一个组件的样式，要么在扫描页单独用 tab。我建议**改组件**，因为其他页面（应用/存储）的 chip 也有同样问题。
3. **review 组的说明收到组标题下** —— 会删掉每行的一句。如果产品上希望每行都提示，请告诉我，我改成 hover 才显示。
